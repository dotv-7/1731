Devin 架构：VM、Session、历史记录、记忆和 GitHub 是怎么交互的

组织 dotv-io · 根据本 session（2026-11-05）实际查到的情况绘制 · 一个 session = 一台独立 VM

开机复制：新 session 启动时，从 ③ 快照复制一整台 VM。三台 VM 的起点相同，之后各改各的。
写入历史：每条消息、每个命令都实时记到 ① 里。你在网页上看到的聊天记录就来自这里，而不是 VM。
同步记忆：启动时从 ② 下载到 ~/memory/v_9c955a；我改完调用 memory_sync 上传合并。别的 session 要下次同步才看得到。
工具调用：我（A）调用 ⑤ 的接口，接口从 ① 里读出 B、C 的记录交给我。只读，而且限于同一个组织。
代码同步：各 VM 里的仓库副本通过代理连到 GitHub。代码要共享，只能经过 GitHub 推送和拉取。
休眠：空闲 30 分钟后，VM 整个存进 ⑥，不再占用机器和用量；唤醒时原样恢复。
东西放在哪三个 session 共享吗
聊天记录 / 命令记录① 云端能互相读（通过工具接口，只读）
长期记忆笔记② 云端 + 每台 VM 一份本地副本共享（需要同步）
初始环境③ 快照起点相同
Secrets / Knowledge / GitHub 连接④ 云端共享
代码（已提交并推送的）GitHub共享
VM 里的文件（未推送的修改、临时文件）各自 VM 的硬盘不共享
终端、运行中的程序、内存各自 VM不共享
